# VOUCHER & RECEIPT ROLE-BASED SCOPING SPECIFICATION
## Comprehensive Step-by-Step Implementation Guide

**Document Purpose**: Define the precise system requirements, current architectural gaps, and step-by-step implementation instructions for enforcing role-based visibility and access scoping across **Vouchers** and **Plot Receipts (Downpayment, EMI Installments, and Full Payments)**.

---

## 1. Executive Summary & Business Rules

### Access Control Matrix

| Role | Voucher Visibility (`/vouchers`) | Receipt Visibility (`/plots/receipts`) | Actions Permitted (Approve / Reject / Edit / Delete) |
| :--- | :--- | :--- | :--- |
| **Super Admin / Admin / Developer / Grant** | **All Vouchers** across all branches. Optional branch dropdown filter. | **All Receipts (DP, EMI, Booking)** across all branches. Optional branch filter. | Full access according to CRUD permissions. |
| **Branch Manager** | **All Vouchers** within their assigned `branchIds`. Can see vouchers generated by cashiers, accountants, and staff in their branch. | **All Receipts** within their assigned `branchIds`. Can see receipts generated by cashiers, accountants, and staff in their branch. | Can approve, reject, or manage items strictly within their assigned branch(es). |
| **Cashier / Accountant / Operator / Staff** | **Only their OWN generated vouchers** (`createdBy === userId`). Cannot see any voucher created by another user. | **Only their OWN generated receipts** (`createdBy === userId`). Cannot see DP, EMI, or booking receipts created by another user. | Can create new and view their own. Cannot approve or reject vouchers/receipts. Cannot view/edit another user's records. |

## 2. Current Architecture & Identified Gaps

### A. Vouchers Module

1. **Model (`server/models/voucher.js`)**:
   - ✅ Has `branchId` (`ref: 'Branch'`) and `createdBy` (`ref: 'User'`).
2. **Controller Query Scoping (`server/controllers/voucher.js` -> `getVouchers`)**:
   - ✅ Logic already checks `isGlobalAdmin`, `isBranchManager` (`query.branchId = { $in: req.user.branchIds }`), and else `query.createdBy = req.userid`.
   - ✅ `getVoucherDetails` already validates branch access for managers and `isOwner` for cashiers/accountants.
3. **CRITICAL DEFECTS in Vouchers**:
   - 🔴 **Router Hard-block**: In `server/router/route.js`, line 260:
     `authorizeRoles('superadmin', 'admin', 'manager', 'demo')` is hardcoded.
     **Neither `cashier` nor `accountant` is included in `authorizeRoles`!**
     When a cashier or accountant tries to access `/vouchers`, Express returns **403 Forbidden** before the controller logic is even reached.
   - 🔴 **Branch Assignment upon Creation**: In `server/controllers/voucher.js` (`createVoucher`), line 185:
     `branchId` assignment prioritizes `targetLedger.employeeId.branchId`. If a cashier at Branch A creates an advance voucher for an employee assigned to Branch B, the voucher gets tagged with Branch B. Consequently, Branch A's manager cannot see it. It must be tagged with the cashier's active branch (`req.user.branchIds[0]`).

---

### B. Receipts Module (Plot DP, EMI Installments, and Full Payments)

1. **Model (`server/models/PlotReceipt.js`)**:
   - 🔴 **MISSING `branchId` FIELD**: `PlotReceipt` only has `createdBy` (`ref: 'User'`). It has NO `branchId` field! Neither `PlotBooking` nor `PlotCustomer` has `branchId`.
2. **Collection Service (`server/services/plots/plotCollection.service.js` -> `collectInstallment`)**:
   - 🔴 **Receipt Creation Missing Branch**: When DP or EMI receipts are created, `branchId` is never assigned or persisted.
3. **List Receipts Scoping (`server/services/plots/plotCollection.service.js` -> `getReceipts`)**:
   - 🔴 **Broken Branch Manager Scoping**:
     Currently lines 976-981 do:
     ```javascript
     query.$or = [
       { createdBy: userId },
       { approvedBy: userId },
       { createdBy: { $exists: false } },
       { createdBy: null },
     ];
     ```
     The branch manager **CANNOT see receipts created by cashiers or accountants** in their branch! They only see receipts created by their own user ID.
   - 🔴 **Cashier/Accountant Data Leak**:
     Lines 984-988 allow cashiers to see `{ createdBy: { $exists: false } }, { createdBy: null }` (all legacy receipts created by any user).
4. **Single Receipt Details Scoping (`plots.controller.js` -> `getReceiptById`, `plotCollection.service.js`)**:
   - 🔴 **Zero Authorization**: `getReceiptById` does not take `req.user`. Any user with `plot_collection: 1` can type any receipt ID into `/plots/receipts/:id` and inspect receipts generated by other users or other branches.
5. **Receipt Mutation Scoping (`updateReceipt`, `deleteReceipt`, `approveReceipt`, `rejectReceipt`)**:
   - 🔴 No verification that the receipt belongs to the user or to the manager's branch before performing updates or reversals.

### Step 3: Database Backfill Script for Existing Receipts

**File**: `server/scripts/backfillReceiptBranches.js`

Create a migration script to populate `branchId` on legacy receipts that have `createdBy`:
```javascript
const mongoose = require('mongoose');
const PlotReceipt = require('../models/PlotReceipt');
const User = require('../models/user');
const Employee = require('../models/employee');
const Branch = require('../models/branch');

async function backfill() {
  await mongoose.connect(process.env.MONGO_URI);
  console.log('Connected to DB for PlotReceipt branch backfill');

  const defaultBranch = await Branch.findOne();
  const receiptsWithoutBranch = await PlotReceipt.find({
    $or: [{ branchId: { $exists: false } }, { branchId: null }]
  });

  console.log(`Found ${receiptsWithoutBranch.length} receipts without branchId`);

  for (const receipt of receiptsWithoutBranch) {
    let resolvedBranchId = null;
    if (receipt.createdBy) {
      const user = await User.findById(receipt.createdBy);
      if (user?.branchIds?.length > 0) {
        resolvedBranchId = user.branchIds[0];
      } else if (user?.employeeId) {
        const emp = await Employee.findById(user.employeeId);
        if (emp?.branchId) resolvedBranchId = emp.branchId;
      }
    }
    receipt.branchId = resolvedBranchId || defaultBranch?._id;
    await receipt.save();
  }

  console.log('Backfill completed successfully');
  process.exit(0);
}

backfill();
```

### Step 5: Enforce Scoping in `plotCollection.service.js` -> `getReceipts`

**File**: [server/services/plots/plotCollection.service.js](file:///c:/Users/good%20nature/OneDrive/Desktop/CODING/Ems-goodnature/server/services/plots/plotCollection.service.js)

Update `getReceipts(filters = {}, user = null)`:

```javascript
async getReceipts(filters = {}, user = null) {
  const query = {};
  if (filters.bookingId) query.bookingId = filters.bookingId;
  if (filters.receiptType) query.receiptType = filters.receiptType;

  // Role-based visibility scoping:
  if (user) {
    const userRole = user.role;
    const isGlobalAdmin = ['superadmin', 'developer', 'admin', 'grant'].includes(userRole);
    const isBranchManager = userRole === 'manager';
    const userId = user._id || user.id;

    if (isGlobalAdmin) {
      // Admin/Superadmin can see all, with optional branchId filter from query
      if (filters.branchId && filters.branchId !== 'all') {
        query.branchId = filters.branchId;
      }
    } else if (isBranchManager) {
      // Branch Manager: See all receipts generated within their assigned branch(es)
      if (Array.isArray(user.branchIds) && user.branchIds.length > 0) {
        query.branchId = { $in: user.branchIds };
      } else {
        // Fallback: If manager has no branchIds assigned, show only their own
        query.createdBy = userId;
      }
    } else {
      // Cashier, Accountant, Operator, Sales, Staff:
      // STRICTLY see ONLY receipts generated by their own user ID!
      query.createdBy = userId;
    }
  }

  // Support date range filtering if provided
  if (filters.startDate || filters.endDate) {
    query.createdAt = {};
    if (filters.startDate) query.createdAt.$gte = new Date(filters.startDate);
    if (filters.endDate) {
      const eDate = new Date(filters.endDate);
      eDate.setHours(23, 59, 59, 999);
      query.createdAt.$lte = eDate;
    }
  }

  const page = parseInt(filters.page) || 1;
  const limit = parseInt(filters.limit) || 20;
  const skip = (page - 1) * limit;

  const [receipts, total] = await Promise.all([
    PlotReceipt.find(query)
      .populate('branchId', 'name branchCode')
      .populate('createdBy', 'name email role')
      .populate({
        path: 'bookingId',
        populate: [
          { path: 'customerId', select: 'name customerId mobile address' },
          { path: 'plotId', populate: { path: 'seriesId' } }
        ],
      })
      .sort({ createdAt: -1 })
      .skip(skip)
      .limit(limit),
    PlotReceipt.countDocuments(query),
  ]);

  return {
    receipts,
    pagination: { page, limit, total, pages: Math.ceil(total / limit) },
  };
}
```
